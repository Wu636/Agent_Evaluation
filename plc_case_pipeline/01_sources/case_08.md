案例 8 状态表法程序设计-单按钮三灯顺序点亮控制基础案例实操训练

用状态表法设计一个按钮依次点亮3盏灯。

| 工艺 | 输入 | 输出 | 状态 |  |  |
| --- | --- | --- | --- | --- | --- |
|  | I0.0 | Q0.0 | Q0.1 | Q0.2 |  |
| 0.待机 | 0 | 0 | 0 | 0 | S0 |
| 1.灯1亮 | 1 | 1 | 0 | 0 | S1 |
| 2.灯2亮 | 1 | 0 | 1 | 0 | S2 |
| 3.灯3亮 | 1 | 0 | 0 | 1 | S3 |

一、训练目的

知识层面：掌握多状态系统的状态表设计方法，理解内部辅助继电器（M寄存器）构建步进状态机的原理，熟记PLC I/O地址映射规范，建立复杂顺序控制的逻辑认知。

实操层面：能够独立完成“一键三灯”的I/O分配，运用状态表法推导逻辑表达式并编写LAD程序，自主排查状态跳变异常、灯光顺序错乱等典型逻辑故障。

思政层面：体会工业控制中“循序渐进”的工序逻辑，培养系统化、模块化的工程设计思维，树立“逻辑清晰方能执行有力”的职业素养。

二、训练步骤

训练启动与角色分配：智能体以「PLC实训指导教师」身份语音开场，学生以「机电实训学员」角色全程一对一语音交互，依托智慧树虚拟仿真平台完成全部训练，无需线下硬件。

基础理论问答

智能体依次语音提问，学生语音作答，回答完毕智能体实时正误反馈，答错推送微课知识点复盘。

问题 1：本案例涉及4个状态（全灭、灯1亮、灯2亮、灯3亮），至少需要多少个内部辅助继电器（M点）来表示这些状态？依据是什么？

问题 2：在状态表法中，“现态”与“次态”的转换通常由什么信号触发？为何不能直接使用按钮的普通常开触点？

问题 3：PLC输出端的公共端（COM）如果悬空，会导致什么现象？上电前必须检查什么？

工业案例实操分析（15分钟）

智能体给出工业案例场景：某自动化设备的工位状态指示塔（三色灯），利用单个确认按钮循环切换“就绪（绿）→运行（黄）→故障（红）→复位（全灭）”状态，模拟车间设备人机交互需求，分层提问：

问题 1：假设M0.0、M0.1、M0.2分别代表灯1、灯2、灯3的点亮状态，请口述状态表中“现态=M0.1（灯2亮）+ 按下按钮”对应的次态是哪个？此时输出逻辑如何变化？

问题 2：编写程序时，为了保证任一时刻只有一个状态激活（即只有一盏灯亮），除了使用互锁电路，还可以利用状态表中的哪种逻辑关系来实现“互斥”？

问题 3：仿真运行时，出现“按第一次按钮，灯1和灯2同时亮”的现象，从状态表逻辑分析，最可能是遗漏了哪个关键逻辑（如状态的复位或置位优先级）？

学生分析完成后，智能体梳理完整解题逻辑：定义4个物理状态→分配状态继电器→绘制状态转移图→填充状态表→逻辑化简→编写互锁程序→加入边沿检测。

优化拓展思路

智能体语音提出拓展问题，学生结合案例作答：

问题 1：如果需要增加“长按3秒按钮，无论当前在哪一步，立即强制跳转回‘全灭’状态”的功能，状态表和程序需要增加哪些部分？

问题 2：在连续生产作业中，若指示灯出现故障（如灯丝烧断），从程序设计角度如何增加“灯故障自检”功能？

学生作答后，智能总结优化核心思路：引入定时器识别长按键、增加输出回检逻辑、状态机设计中的“异常状态”处理。

课程思政专项互动

智能体切换思政引导身份语音提问：

问题 1：状态机中每一个状态的稳定是下一个动作正确的前提，结合本次实训谈谈“脚踏实地，一步一个脚印”的作风在工程技术中的重要性。

问题 2：国产PLC汇川编程软件在状态机编程上提供了丰富的向导功能，作为机电专业学生，如何看待工具创新对提升工程设计效率的作用？

训练小结

智能体语音整体回顾状态表法设计流程、状态互锁机制及边沿检测的应用，点评学生在多状态逻辑推导中的表现，重点标注对“状态互斥”和“循环复位”逻辑的理解薄弱环节。
